↻ Циклическая LLM: обычный трансформер и OrbitLM

Проследите путь токена через обычный трансформер и OrbitLM. Главное отличие — не новый промпт или агентный цикл: OrbitLM многократно применяет один и тот же стек трансформера внутри модели.

Обычная плотная LLM

Разные веса на каждой глубине

Токен проходит стек слоев один раз. У каждого слоя собственные параметры.

Токен → L1 → L2 → L3 → Выход
hL = fL(...f2(f1(h0)))
  • Один прямой проход через стек
  • Уникальные веса L1, L2, ..., LN
  • Вычисления растут вместе с числом хранимых слоев
Циклическая языковая модель

Большая глубина за счет повторного использования весов

OrbitLM пропускает представление через один общий стек из 24 слоев до четырех раз.

h0 → Wshared → h1 повтор ×4
hk = Fshared(hk−1),   k = 1...4
  • Одни и те же Wshared используются на каждом проходе
  • После каждого прохода выходной gate оценивает готовность
  • Больше вычислений не означает вчетверо больше хранимых слоев
24общих слоя трансформера
4максимум рекуррентных проходов
1,86 млрдуникальных параметров
5,24 млрдприменений параметров на генерируемый токен

Эмбеддинг токена

Промпт разбивается на токены и преобразуется в векторы. Нажмите «Запуск» или «Следующий шаг», чтобы проследить путь представления.

Что делает выходной gate?

После каждого прохода небольшой обучаемый gate оценивает, готово ли представление токена к выводу. При генерации можно задать фиксированный exit_at_step или порог вероятности выхода. Меньше проходов — быстрее, но потенциально слабее.

Каков компромисс?

Повторное использование весов увеличивает эффективную глубину без четырех отдельных стеков слоев. Но вычисления остаются: OrbitLM применяет около 5,24 млрд параметров на токен и хранит отдельные K/V-записи для каждого прохода — 96 слоевых записей на токен.

Циклическая LLM ≠ агентный цикл

Внутренний цикл: повторные нейросетевые вычисления при генерации токена. Внешний агентный цикл: модель → вызов инструмента → наблюдение → модель. OrbitLM может работать внутри TAO, но не заменяет его.

📈 Объяснение ключевых концепций

Разберитесь в базовых компонентах современных систем ИИ-агентов.

Model Context Protocol (MCP)

⚙

Стандартизированные описания инструментов и ресурсов, позволяющие LLM безопасно вызывать внешние возможности. MCP предоставляет единый интерфейс для обнаружения и выполнения инструментов, а также обработки результатов.

HyDE (эмбеддинги гипотетических документов)

🏼

Сгенерируйте гипотетический ответ, чтобы сформировать более качественный поисковый запрос. Вместо прямого поиска по запросу пользователя HyDE создает синтетический документ, похожий на идеальный ответ, а затем использует его эмбеддинги для поиска.

TAO: мысль — действие — наблюдение

✨

Цикл, похожий на ReAct, в котором агент чередует рассуждение, выполнение действий и получение обратной связи. Это позволяет автономно решать задачи посредством итеративного исследования.

Генерация с дополнением поиском (RAG)

📄

Улучшайте ответы LLM, извлекая релевантные документы из базы знаний. RAG объединяет возможности больших языковых моделей с внешними актуальными источниками информации.

DSPy (декларативный самоулучшающийся Python)

🛠

Фреймворк для программирования с фундаментальными моделями. DSPy позволяет определять конвейеры, в которых LLM могут программно генерировать и оптимизировать собственный код для решения сложных задач.

Мультиагентные системы

👤

Координируйте несколько специализированных агентов для решения сложных задач. Среди шаблонов — «агент-критик» для контроля качества, «агент-координатор» для распределения задач и ансамблевые подходы.
