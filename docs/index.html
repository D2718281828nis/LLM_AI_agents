Core Concept

↻ Looped LLM: Dense Transformer vs OrbitLM

Follow a token through a conventional transformer and OrbitLM. The key difference is not another prompt or agent loop: OrbitLM repeatedly applies the same transformer stack inside the model.

Conventional dense LLM

Different weights at every depth

A token passes through the layer stack once. Each layer has its own parameters.

Token → L1 → L2 → L3 → Output
hL = fL(...f2(f1(h0)))
  • One forward pass through the stack
  • Unique L1, L2, ..., LN weights
  • Compute grows with the number of stored layers
Looped language model

More depth through weight reuse

OrbitLM sends the representation through one shared 24-layer stack up to four times.

h0 → Wshared → h1 repeat ×4
hk = Fshared(hk−1),   k = 1...4
  • The same Wshared is reused at every pass
  • An exit gate scores readiness after each pass
  • More compute does not mean four times more stored layers
24shared transformer layers
4maximum recurrent passes
1.86Bunique parameters
5.24Bparameter applications per generated token

Token embedding

What does the exit gate do?

After every pass, a small learned gate scores whether the token representation is ready for output. Generation can use a fixed exit_at_step or an exit-probability threshold. Fewer passes are faster, but can be weaker.

What is the trade-off?

Weight reuse increases effective depth without four separate layer stacks. It does not eliminate computation: OrbitLM applies about 5.24B parameters per token and keeps separate K/V entries for every pass — 96 layer entries per token.

Looped LLM ≠ agent loop

Inner loop: repeated neural computation while producing a token. Outer agent loop: model → tool call → observation → model. OrbitLM can run inside TAO, but does not replace it.

📈 Key Concepts Explained

Understand the fundamental building blocks of modern AI agent systems.

Model Context Protocol (MCP)

⚙

Standardized tool and resource descriptions that enable LLMs to safely call external capabilities. MCP provides a consistent interface for tool discovery, execution, and result handling.

HyDE (Hypothetical Document Embeddings)

🏼

Generate a hypothetical answer to form better retrieval queries. Instead of searching with the user's query directly, HyDE creates a synthetic document that represents what the ideal answer would look like, then uses its embeddings for retrieval.

TAO: Think-Act-Observe

✨

A ReAct-like loop where the agent alternates between reasoning (Thinking), executing actions (Acting), and receiving feedback (Observing). This enables autonomous problem-solving through iterative exploration.

Retrieval-Augmented Generation (RAG)

📄

Enhance LLM responses by retrieving relevant documents from a knowledge base. RAG combines the power of large language models with external, up-to-date information sources.

DSPy (Declarative Self-improving Python)

🛠

A framework for programming with foundation models. DSPy enables you to define pipelines where LLMs can generate and optimize their own code to solve complex tasks programmatically.

Multi-Agent Systems

👤

Coordinate multiple specialized agents to solve complex problems. Patterns include Critic-Agent (quality control), Coordinator-Agent (task distribution), and ensemble approaches.
